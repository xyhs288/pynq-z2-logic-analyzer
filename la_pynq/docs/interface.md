# 寄存器接口契约（冻结版 v2）

> **本文件是三人协作的接口约定。改动必须先改本文件、再改 RTL，并通知另外两人。**

## 版本说明

- **v1 的缺陷**：地址位宽 6 位（只有 16 个寄存器），只够覆盖采集功能；
  协议解码和时序统计做出来之后没有地址可挂。
  且 v1 文档写 `0x0C = DEPTH`，而早期实现写成 `0x0C = TRIG_MODE`，两边不一致。
- **v2（本版）**：地址位宽扩到 **8 位**（64 个寄存器），重新排布，无冲突。**以本文件为准。**

## 一、地址总表

### 采集控制

| 偏移 | 名称 | R/W | 位定义 |
|---|---|---|---|
| `0x00` | `CTRL` | RW | bit0 = arm（写 1 布防）；bit1 = soft reset；bit2/bit3 = **保留**（原板内自测源，已删除，写 1 无效果）；**bit4 = free run**（1 = 不触发、缓冲一直写，PS 可以随时读最新 N 点做滚动显示；此模式与触发互斥）；**bit5 = Pmod B 输出使能**（1 = 驱动 8 根测试信号针，0 = 高阻，复位默认 **1**） |
| `0x04` | `STATUS` | RO | bit0 = armed，bit1 = trigged，bit2 = full，bit3 = clr_busy |
| `0x08` | `DIV` | RW | [31:0] 采样分频，采样率 = FCLK_CLK0 / DIV（本板 62.5 MHz / DIV，复位默认 1250 => 50 kHz） |
| `0x0C` | `DEPTH` | RW | [15:0] 本次要读回的采样点数（**只影响读出长度**，物理缓冲深度固定） |
| `0x10` | `TRIG_MODE` | RW | [2:0] 0=上升沿 1=下降沿 2=高电平 3=低电平 **4=协议字节匹配** |
| `0x14` | `TRIG_CHAN` | RW | [2:0] 触发通道 0–7（模式 4 时忽略） |
| `0x18` | `TRIG_VALUE` | RW | [7:0] 电平 / 字节匹配的目标值 |
| `0x1C` | `TRIG_MASK` | RW | [7:0] 掩码（本版保留，未参与比较） |
| `0x20` | `PRE_TRIG` | RW | [15:0] 触发点之前保留多少点 |
| `0x24` | `CHAN_EN` | RW | [7:0] 通道使能位图（本版保留，复位 0xFF） |

### 协议解码

| 偏移 | 名称 | R/W | 位定义 |
|---|---|---|---|
| `0x28` | `PROTO_SEL` | RW | [1:0] 0=UART 1=SPI 2=I2C（选哪个解码器接到匹配器） |
| `0x2C` | `PROTO_DIV` | RW | [31:0] UART 波特率分频（一个位周期含多少 clk） |
| `0x30` | `PROTO_BYTE` | RO | [7:0] 最近解出的字节 |
| `0x34` | `PROTO_STAT` | RO | bit0 = **曾经**解码出过字节（粘滞），bit1 = **曾经**出现帧错误（粘滞），bit2 = 应答位（I2C，0=ACK，实时） |

**三个解码器各自盯固定的通道，不能改**：

| 协议 | 用到的通道 |
|---|---|
| UART | `CH0` = RX |
| SPI | `CH1` = SCLK，`CH2` = MOSI，`CH3` = CS_N |
| I2C | `CH4` = SCL，`CH5` = SDA |

⇒ Pmod B 的 I2C 波形（针 7/8）因此接回 **CH4/CH5**，正好对上解码器的输入。
⇒ 采集通路只有一条：Pmod A 八路引脚。板内不再有替代输入的自测源。

> ### ⚠️ 为什么 bit0 / bit1 必须做成"粘滞"而不是实时脉冲
>
> 解码器的 `valid` 和 `frame_err` 都是**单拍脉冲**（62.5 MHz 下 16 ns 宽）。
> PS 走 AXI 读寄存器，一次事务就是几十个时钟，**读到的永远会是 0** —— 而且不报错，
> 表现为"明明总线上有数据，寄存器却一直说没解码出东西"。
>
> 所以这两个位做成粘滞标志：**一旦出现过就保持为 1，直到软复位（`CTRL.bit1`）清除**。
> 这是本设计里最容易踩的一个坑，写 PS 侧代码时不要按"实时脉冲"去理解。
>
> 对照：`STATUS`（`0x04`）里的 armed / trigged / full **是实时状态**，不是粘滞量，
> 轮询时读到的就是当前值；而 `trigged` 只在"触发后到抓满前"这段时间里为 1，
> 所以 **PS 轮询 `full` 比轮询 `trigged` 可靠**。

### 数据读出

| 偏移 | 名称 | R/W | 位定义 |
|---|---|---|---|
| `0x80` | `MEM_ADDR` | RW | [15:0] 写 = 设定物理读地址；读 = 返回该地址的采样值（低 8 位有效） |
| `0x84` | `WR_PTR` | RO | [15:0] 当前写指针 |
| `0x88` | `STOP_PTR` | RO | [15:0] 冻结时的写指针 = **时间顺序上最老的那个点的物理地址** |

## 二、为什么读出用"两寄存器寻址"而不是自增窗口

v1 曾计划用 `0x40` 自增窗口：读一次前进一格。**已否决。**

理由：自增窗口的地址在 PL 内部维护，PS 侧一旦发生中断、重试、或某次读被丢弃，
**地址就永久错位**，而且现象是"波形整体平移"，极难归因。
显式寻址多写一次寄存器，但**每一步都可复现、可重放**。

三人协作的代码，**可靠性优先于省一次寄存器写**。

## 三、PS 标准使用流程（`la_driver.py` 照抄这个顺序）

```
 1. 写 DIV / PRE_TRIG / TRIG_MODE / TRIG_CHAN / TRIG_VALUE
 2. 写 PROTO_SEL / PROTO_DIV              （若用协议触发）
 3. 写 CTRL.bit1 = 1 软复位，再写 0
 4. 写 CTRL.bit0 = 1                     布防
 5. 轮询 STATUS，等 bit2(full) = 1
 6. 读 STOP_PTR 得到时间顺序起点
 7. 循环 DEPTH 次：
      写 MEM_ADDR = (STOP_PTR + i) & (物理深度 - 1)
      读 MEM_ADDR
 8. 统计（可选）：
      写 STAT_CTRL.bit1 = 1 清空 → 轮询 STAT_STAT.clr_busy 落下
      写 STAT_CTRL.bit0 = 1 使能 → 采集
      写 STAT_CTRL.bit2 = 1 启动扫描 → 轮询 STAT_STAT.pct_valid
      读 0x4C – 0x78
```

**第 7 步的 `& (物理深度 - 1)` 不能省** —— `STOP_PTR + i` 会越过缓冲末尾回绕。

## 四、给 PS 侧的提醒

- 所有寄存器是 **32 位小端、单次访问**，不要按字节拆分读写；
- `STATUS` 是组合输出，轮询不必加延时，但两次读之间至少隔一个 AXI 事务；
- **写只读寄存器不会产生响应错误**（当前实现直接忽略）。
  因此地址拼错不会报错、只会读到 0 —— **调 "读不到数据" 时第一件事是核对地址**；
- `STAT_CTRL.bit1`（清空）是**保持型**信号，不是单拍脉冲。
  清空引擎要跑 256 个时钟，中途撤掉会导致直方图清一半。
  **正确做法：置 1 → 轮询 `clr_busy` 落下 → 再置 0。**
- `STAT_STAT.pct_valid` **也是保持型**：扫描完成后一直保持 1，直到下一次启动扫描
  （`STAT_CTRL.bit2`）或软复位（`CTRL.bit1`）把它清掉。这样 PS 一次 AXI 轮询就能看到结果。
  > **踩过的坑**：最初把它实现成单拍——`S_DONE` 置 1，下一拍回到 `S_IDLE` 又被清 0，
  > 只有 **16 ns** 宽，PS 走 AXI 永远读不到（表现为"扫描好像没跑"）。
  > 仿真没发现，因为 testbench 是**逐拍等待**的。
  > 这和 `axi_regs` 的 `ready` 预先就位那次是同一类问题：
  > **逐拍能看见的东西，AXI 批量读看不见。**
